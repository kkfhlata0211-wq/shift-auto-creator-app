# 医療・介護向け PC専用シフト自動作成Webアプリケーション

医療および介護現場の複雑な労務制約（変形労働時間制、連続勤務制限、夜勤翌日ルール、NGペア同席回避、FTE・必要人数など）を考慮しながら、1ヶ月分のシフト表を自動生成・リアルタイム検証・微調整できるPC専用Webアプリケーションです。

## 主な機能
- **1ヶ月マトリクス表示**: PCのワイド画面に最適化した横軸（日付・行事）・縦軸（スタッフ）の固定スクロールUI。
- **シフト自動生成エンジン**:
  - 希望シフト（公休・有休など）を先に反映（確定ロック優先。希望の優先度フラグによる差はなし）。
  - 夜勤可能スタッフの夜勤回数、および設定時の土日勤務回数を考慮。
  - NGペア（同一シフト同席禁止）の自動回避。
  - 候補選定時に連勤上限を考慮（候補不足時の救済処理などにより超過する場合があります）。
- **リアルタイム制約検証（バリデーション）**:
  - 法定・契約労働時間オーバー警告。
  - 連勤オーバー・夜勤翌日ルール違反のセルハイライト。
  - 時間帯・シフト別必要人数の不足判定（画面下部フッターの赤色ハイライト）。
- **手動微調整・確定ロック**:
  - マトリクスセルをクリックして勤務区分を即時変更。
  - ピン留め（確定ロック）したセルは自動生成時も維持。
- **データ永続化 & ファイル入出力**:
  - SQLite（sql.js + IndexedDB）への自動保存（ブラウザ内完全ローカル動作）。
  - 初回起動時に旧LocalStorageデータからの自動マイグレーション。
  - JSON形式での設定・シフトバックアップ・復元。
  - Excelで開けるShift-JIS / UTF-8 BOM付きCSV形式エクスポート。

## 自動シフト作成のロジック

自動作成は、全体の最適解を探索する方式ではなく、決められた順序で割り当てる貪欲法です。先に決まった割当が後続の候補に影響します。

1. **既存の確定ロックを維持**します。ロック済み以外のセルは、以下の処理で再作成されます。
2. **希望シフトを反映**します。希望の優先度フラグによる扱いの差はなく、ロック済みセルが優先されます。
3. **パートの曜日固定シフトを反映**します。希望またはロックによる割当がある日は上書きしません。
4. **夜勤・明番を割り当て**ます。夜勤可能なスタッフを対象に、連勤上限、前回の夜勤からの日数、翌日以降の割当、パートの勤務上限などを確認します。夜勤回数の少ないスタッフを優先し、可能な場合は翌日を明番、その翌日を公休（有休希望があれば有休）にします。
5. **日中の必要枠を日付順に埋めます**。早番・日勤・遅番について、既存割当を差し引いた不足枠を作ります。候補はパートの勤務可能枠を考慮した後、スコア順に選びます。スコアには連勤や休日の並び、労働時間・週の勤務日数、土日勤務回数、各日中シフトの担当回数、希望シフト、スキルレベルが影響します。NGペアが有効な場合、同じ日・同じシフトになる候補は除外します。
6. **残りの勤務日・休日を割り当て**ます。原則は公休（有休希望があれば有休）です。正社員は目標労働時間に届かない場合、追加の日勤を割り当てることがあります。
7. **正社員の月間労働時間を調整**します。目標より少ない場合は条件を満たす公休を日勤に、超過する場合は日中シフトを公休に変更し、目標時間への一致を試みます。
8. **生成後に制約を検証**します。連勤、夜勤後の勤務、労働時間、必要人数、NGペアなどを確認し、違反や不足を画面に表示します。

### 現在の制約・注意点

- 貪欲法のため割当のやり直し（バックトラック）はせず、条件によっては必要人数を満たせないことがあります。
- 通常の候補がいない場合、一部の勤務上限を緩和する救済処理を行うことがあります。生成結果は検証で確認してください。
- 夜勤の必要人数設定にかかわらず、夜勤が未割当の日に新しく割り当てるのは最大1人です。
- 勤務間インターバル、夜勤翌日のルール設定、夜勤平準化設定、日付ごとの個別必要人数は、現在の自動生成・検証処理では参照されていません。夜勤回数の平準化は自動生成処理内で常に行われますが、既存のロック・希望による夜勤は平準化カウンターに含まれません。

## 技術スタック
- **フロントエンド**: React 18, TypeScript, Tailwind CSS, Vite
- **データベース**: SQLite (sql.js WASM + IndexedDB 永続化)
- **アイコン**: Lucide React
- **ビルドツール**: Vite, TypeScript (Strict Mode)

## 開発・起動手順
```bash
# 依存関係のインストール
npm install

# 開発サーバー起動
npm run dev

# 本番ビルド
npm run build
```
